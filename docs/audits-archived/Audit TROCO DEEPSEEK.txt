2.2 — Remplacer alert() et window.confirm() par tes propres modales
Tu as déjà TransactionSuccessModal, NotificationPill, EmptyState… mais tu utilises encore alert() et window.confirm() à une quinzaine d'endroits.

js
// ❌ Actuel
if (window.confirm(t('confirmDeleteText'))) { ... }

// ✅ Cible
const confirmed = await confirmDialog({
  title: t('deleteListingTitle'),
  message: t('confirmDeleteText'),
  confirmLabel: t('delete'),
  destructive: true,
});
Crée un useConfirm() hook + un <ConfirmDialog /> global. Impact UX énorme : ton app est premium, ces boîtes natives cassent tout.

2.3 — Corriger les fuites mémoire (setTimeout + listeners)
Partout où tu as :

js
setTimeout(() => setSaveMessage(''), 6000);
Si le composant démonte avant, tu écris sur un composant mort. Solution :

js
// hooks/useTimeout.js
function useSafeTimeout() {
  const timersRef = useRef(new Set());
  useEffect(() => () => {
    timersRef.current.forEach(clearTimeout);
    timersRef.current.clear();
  }, []);
  return useCallback((fn, delay) => {
    const id = setTimeout(() => {
      timersRef.current.delete(id);
      fn();
    }, delay);
    timersRef.current.add(id);
    return id;
  }, []);
}
Remplace tous les setTimeout liés au state par safeTimeout.

2.4 — localStorage synchrone dans le listener Firestore
js
unsubDoc = onSnapshot(userDocRef, async (docSnap) => {
  // ...
  window.localStorage.setItem('troco_user_profile', JSON.stringify(updated)); // ⚠️ bloquant
});
À chaque update Firestore, tu sérialises un gros objet en synchrone sur le thread UI. Sur mobile, ça micro-freeze.

Fix : debounce + IndexedDB (idb-keyval) ou écrire uniquement les champs modifiés (tokens, euros, kyc, plus — pas tout le profil).

2.5 — Dépendances useEffect bricolées
js
useEffect(() => {
  // ...
}, []); // ⚠️ devrait dépendre de profile?.uid, etc.
Plusieurs hooks écoutent des choses qui changent (uid) mais ne se re-souscrivent pas. Risque : si l'utilisateur change de compte sans reload, tu gardes les listeners du compte précédent.

Fix : ajoute les vraies deps, ou utilise des refs pour les valeurs "latest" (pattern useEvent de React 18.3+).

2.7 — console.warn / console.error en prod
Crée un logger :

js
// utils/logger.js
const isDev = import.meta.env.DEV;
export const logger = {
  warn: (...a) => isDev && console.warn(...a),
  error: (...a) => { console.error(...a); Sentry?.captureException?.(a[0]); },
};
Et branche Sentry (ou LogRocket/Bugsnag). Sans ça, tu es aveugle en prod sur mobile.

Beaucoup de props dérivées passées en cascade → risque de re-renders en chaîne. Utilise React.memo sur FeedCardItem, ChatSection, MapSection
